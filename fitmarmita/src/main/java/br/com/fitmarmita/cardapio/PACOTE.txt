CONCEITO: Relacionamento N:M (muitos pra muitos) com JPA
--------------------------------------------------------
Uma marmita pode ter varias tags (low-carb + sem-gluten).
Uma tag pode estar em varias marmitas.

Em Marmita.java:
  @ManyToMany(fetch = FetchType.LAZY)
  @JoinTable(
      name = "marmita_tag",
      joinColumns = @JoinColumn(name = "marmita_id"),
      inverseJoinColumns = @JoinColumn(name = "tag_id")
  )
  private Set<Tag> tags = new HashSet<>();

A migration V001 ja criou as tabelas marmita, tag e marmita_tag.

DESAFIO TECNICO: Filtro multiplo (US04 TA2)
-------------------------------------------
"Selecionando 'Low Carb' + 'Sem Gluten', mostre apenas marmitas que tem AS DUAS tags"

Isso e uma query JPQL com GROUP BY e HAVING. No MarmitaRepository:

  @Query("""
      SELECT DISTINCT m FROM Marmita m
      JOIN m.tags t
      WHERE m.semanaReferencia = :semana
        AND m.ativa = true
        AND t.slug IN :tagsSlugs
      GROUP BY m
      HAVING COUNT(DISTINCT t.slug) = :totalTags
  """)
  List<Marmita> findByTodasTags(LocalDate semana, List<String> tagsSlugs, long totalTags);

Quando o cliente envia ?tags=low-carb,sem-gluten:
  - totalTags = 2
  - HAVING COUNT(DISTINCT t.slug) = 2 garante que a marmita tem AMBAS

Endpoints sugeridos:
  GET /api/v1/cardapio/semanal                            (sem filtro)
  GET /api/v1/cardapio/semanal?tags=low-carb,vegetariana  (com filtro)
  GET /api/v1/marmitas/{id}                                (detalhes)

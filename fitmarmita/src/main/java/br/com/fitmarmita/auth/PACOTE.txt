Pacote: auth
============

Atende US02 (Login). Depende de que o pacote usuario esteja pronto.

Organize em sub-pacotes:
  auth/
  ├── security/     JwtService.java, JwtAuthenticationFilter.java
  ├── dto/          LoginRequest.java, LoginResponse.java
  ├── service/      AuthService.java
  └── controller/   AuthController.java

CONCEITO CENTRAL: JWT (JSON Web Token)
--------------------------------------
Como APIs REST sao stateless (sem sessao no servidor), o cliente precisa
provar que esta logado em CADA requisicao. O JWT resolve isso:

1. Cliente envia email/senha em POST /api/v1/auth/login
2. Backend valida, gera um token JWT assinado com chave secreta
3. Cliente guarda o token (em localStorage no frontend)
4. Em todas as requisicoes seguintes, o cliente manda no header:
   Authorization: Bearer eyJhbGc...
5. Backend valida assinatura do token e identifica o usuario

ORDEM DE IMPLEMENTACAO:

PASSO 1 - JwtService
--------------------
Crie auth/security/JwtService.java:
- @Service
- Injete chave secreta via @Value("${fitmarmita.jwt.secret}")
- Crie SecretKey com Keys.hmacShaKeyFor(secret.getBytes())
- Metodo gerarToken(Usuario u): retorna String JWT com claims (id, email, nome, exp)
- Metodo extrairEmail(String token): le o subject do token
- Metodo tokenValido(String token): verifica assinatura e expiracao

Use a biblioteca jjwt (ja esta no pom.xml).

PASSO 2 - JwtAuthenticationFilter
---------------------------------
Crie auth/security/JwtAuthenticationFilter.java:
- @Component
- estende OncePerRequestFilter (filtro Spring que roda 1 vez por request)
- No doFilterInternal:
   1. Pega header "Authorization", verifica se comeca com "Bearer "
   2. Se sim, extrai o token
   3. Valida com JwtService
   4. Busca o Usuario no UsuarioRepository pelo email do token
   5. Cria UsernamePasswordAuthenticationToken e seta no SecurityContext
   6. Chama chain.doFilter(request, response) para continuar

Esse filtro e o "porteiro" da API. Toda request passa por ele.

PASSO 3 - DTOs
--------------
LoginRequest: record com email e senha validados
LoginResponse: record com (token, tipo="Bearer", usuario: UsuarioResponse)

PASSO 4 - AuthService
---------------------
Logica do login:
- Busca usuario por email (se nao existir, BusinessException)
- Verifica se conta esta bloqueada
- passwordEncoder.matches(senha, hashDoBanco)
- Se senha errada: incrementa tentativasLogin, bloqueia se >= 5 (TA4)
- Se senha certa: zera tentativas, gera token, retorna LoginResponse

PASSO 5 - AuthController
------------------------
POST /api/v1/auth/login -> LoginResponse

PASSO 6 - Habilitar protecao no SecurityConfig
----------------------------------------------
Volte no SecurityConfig (pacote config) e:
- requestMatchers("/api/v1/auth/**", "/api/v1/usuarios").permitAll()
- anyRequest().authenticated()
- addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class)

PASSO 7 - Teste
---------------
1. Cadastre um usuario via /usuarios
2. Faca login via /auth/login -> recebe token
3. Tente acessar endpoint protegido sem token -> 401
4. Acesse com header "Authorization: Bearer <token>" -> 200

Bonus (criterios da US02):
  TA1: login com credenciais validas retorna token
  TA2: senha errada retorna mesma mensagem que email errado (evita enumeracao)
  TA3: esqueci-senha (deixe para depois, exige envio de email)
  TA4: 5 tentativas erradas bloqueiam por 15 minutos

Pacote: usuario
===============

Este e o primeiro modulo a implementar. Atende US01 (Cadastro de Usuario).

Organize em sub-pacotes:
  usuario/
  ├── entity/       Usuario.java
  ├── repository/   UsuarioRepository.java
  ├── dto/          CadastroUsuarioRequest.java, UsuarioResponse.java
  ├── service/      UsuarioService.java
  └── controller/   UsuarioController.java

ORDEM DE IMPLEMENTACAO (de baixo pra cima):

PASSO 1 - Entity (camada mais baixa)
------------------------------------
Crie usuario/entity/Usuario.java com:
- @Entity, @Table(name = "usuario")
- Campos: id (Long, @Id @GeneratedValue), nome, email (unique), senhaHash,
  telefone, ativo, createdAt, updatedAt
- Use Lombok: @Getter, @Setter, @NoArgsConstructor, @AllArgsConstructor, @Builder
- Use @CreationTimestamp e @UpdateTimestamp para os campos de data

Conceito a aprender: mapeamento objeto-relacional (ORM) com JPA. A classe Usuario
em Java vira a tabela usuario no Postgres automaticamente.

PASSO 2 - Repository
--------------------
Crie usuario/repository/UsuarioRepository.java:
- interface que estende JpaRepository<Usuario, Long>
- Adicione metodos: Optional<Usuario> findByEmail(String email)
                     boolean existsByEmail(String email)

Conceito: Spring Data JPA gera a implementacao automaticamente baseada
no nome do metodo. Voce nao escreve SQL nenhum.

PASSO 3 - DTOs (records do Java)
--------------------------------
Crie usuario/dto/CadastroUsuarioRequest.java como record:
  public record CadastroUsuarioRequest(
      @NotBlank @Size(min = 3) String nome,
      @NotBlank @Email String email,
      @NotBlank @Size(min = 8) String senha,
      String telefone
  ) {}

Crie usuario/dto/UsuarioResponse.java tambem como record (sem a senha):
  public record UsuarioResponse(Long id, String nome, String email, ...) {
      public static UsuarioResponse from(Usuario u) { ... }
  }

Conceito: NUNCA exponha a entidade JPA diretamente no controller. DTOs separam
o que esta no banco do que voce envia/recebe pela API.

PASSO 4 - Service (regra de negocio)
------------------------------------
Crie usuario/service/UsuarioService.java:
- @Service
- @RequiredArgsConstructor para injetar UsuarioRepository e PasswordEncoder
- Metodo cadastrar(CadastroUsuarioRequest request) que:
   1. Verifica se email ja existe -> se sim, lanca BusinessException
   2. Codifica senha com passwordEncoder.encode()
   3. Salva usuario no banco
   4. Retorna UsuarioResponse.from(usuario)

Conceito: a camada de service nao conhece HTTP. Ela recebe DTOs, aplica regras,
chama o repository e retorna DTOs. Essa separacao facilita testes unitarios.

PASSO 5 - Controller
--------------------
Crie usuario/controller/UsuarioController.java:
- @RestController, @RequestMapping("/api/v1/usuarios"), @RequiredArgsConstructor
- POST / -> recebe @Valid @RequestBody CadastroUsuarioRequest, retorna UsuarioResponse
- @ResponseStatus(HttpStatus.CREATED) no metodo de cadastro

Conceito: o controller e fino. Ele so traduz HTTP em chamadas ao service.

PASSO 6 - Teste de aceitacao
----------------------------
Com tudo pronto, teste no Swagger UI (http://localhost:8080/swagger-ui.html)
ou via curl:

  curl -X POST http://localhost:8080/api/v1/usuarios \
    -H "Content-Type: application/json" \
    -d '{"nome":"Joao","email":"joao@email.com","senha":"senha12345"}'

Devera retornar HTTP 201 com o usuario criado (sem a senha no JSON).

Cheque tambem os criterios da US01:
  - TA1: cadastro com email valido funciona
  - TA2: email duplicado retorna 400 com mensagem
  - TA3: senha com menos de 8 caracteres retorna 400
  - TA4: campos em branco retornam 400 com lista de erros
